## Detection surface

Potential source signals include request frequency, timing, HTTP headers, session behavior, browser or headless characteristics, repeated patterns, 429 responses, 403/block responses, and CAPTCHA or interstitial responses.

Our implementation uses one permitted public API, low request volume, normal request headers, bounded retries, and an explicit stop rule. We do not bypass CAPTCHA, authentication, access controls, or IP restrictions.

## Ingestion strategy

The demo uses a public, low-risk endpoint. It uses descriptive headers and bounded pacing, but never attempts CAPTCHA bypassing, stealth fingerprinting, credential automation, or proxy evasion.

## Ingestion strategy

A small source adapter fetches one public JSON feed, normalizes the records, and stores only the fields needed by the reviewer. Manual and scheduled runs share one path.

## Resilience approach

Timeouts, bounded retries, exponential backoff, malformed-record handling, durable run history, and source-ID uniqueness keep failures visible and retries safe.

## Plan-B fallback

If the source changes or becomes unavailable, swap the adapter to another permitted public RSS/API feed or a sandbox feed without changing the database or dashboard contract.

## Ethical / ToS boundary

We stop at public, permitted data. Production access should use an official API, licensed feed, or written permission. We do not circumvent access controls or automate accounts.

## AI usage and verification

AI can assist with scaffolding, but the source boundary, failure behavior, schema, and tests are personally verified and kept simple enough to explain line by line.
